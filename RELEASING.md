# Releasing

## 1. Create a signing keystore (once, and never lose it)

Play identifies your app by its signing key. **If you lose this keystore you can
never update the app again** — you would have to publish it under a new package
name and lose your users. Back it up somewhere that is not this repository.

```bash
keytool -genkey -v \
  -keystore ~/retrobeat-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias upload
```

Then create `android/key.properties` (this file is gitignored — it holds the
password, so it must never be committed):

```properties
storeFile=/absolute/path/to/retrobeat-upload.jks
storePassword=<the store password you just chose>
keyAlias=upload
keyPassword=<the key password you just chose>
```

Without this file a release build still *succeeds*, but it is signed with the
debug key and Play will reject it. The Gradle build prints a warning saying so
rather than handing you an artifact that looks fine and is not.

## 2. Bump the version

`pubspec.yaml`:

```yaml
version: 1.0.0+1
#       ^^^^^ versionName (what users see)
#             ^ versionCode (must increase on every upload)
```

## 3. Build

Play requires an **App Bundle**, not an APK:

```bash
flutter build appbundle --release
# build/app/outputs/bundle/release/app-release.aab
```

APKs, for sideloading and testing:

```bash
flutter build apk --release --split-per-abi
```

Sanity-check the release build on a real device before uploading — R8 is on for
release, and shrinker breakage never shows up in debug:

```bash
flutter build apk --release
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

Play against a real library, open the equalizer, and lock the screen. If a
release-only crash appears, it is almost certainly a missing keep rule in
`android/app/proguard-rules.pro`.

## 4. Play Console listing

Assets are generated by `tool/generate_icons.py` into `store/`:

| Asset | Requirement |
|---|---|
| App icon | 512 × 512 PNG, 32-bit |
| Feature graphic | 1024 × 500 PNG |
| Phone screenshots | at least 2, 16:9 or 9:16, min 320 px |

## 5. Data safety

Read `PRIVACY.md` first — it is the source of truth for what to declare.

The short version for the Data safety form:

- **Data collected: none.** The app has no network access, no analytics, no
  accounts, no crash reporting.
- **Data shared: none.**
- The app requests **RECORD_AUDIO**, which the form will ask about. It is used
  *only* for the opt-in audio-reactive visualiser: Android gates
  `android.media.audiofx.Visualizer` behind that permission even when the audio
  being analysed is the app's own playback. Nothing is recorded, stored, or
  transmitted. If you would rather not answer questions about it, delete the
  `<uses-permission android:name="android.permission.RECORD_AUDIO"/>` line from
  `AndroidManifest.xml` — the visualiser then quietly stays decorative, which is
  its default anyway.

## Known gaps before a public release

- The equalizer is Android-only (just_audio has no iOS equaliser); the iOS build
  says so rather than pretending.
- Lockscreen and headset controls have not been verified on a physical device.
- There is no crash reporting, deliberately — adding one would mean the "no data
  collected" claim above stops being true.
